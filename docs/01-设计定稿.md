# RemoteDSH 设计定稿

> 目标：让 DSH（本机 harness）**直接操作任意一台目标电脑**——不要求目标机装 Node、不要求用户在目标机上做网络配置、不要求目标机有公网 IP。用户只需在目标机上双击一个 exe，把终端上显示的配对串（或二维码截图）发给我，我就能在那台机器上执行命令、收发文件、跑 `.mjs` 工具。
>
> 命名：项目名 **RemoteDSH**；二进制名 **rdsh**（Remote DSH agent）。面板文案一律「远程 DSH 正在连接」，不出现任何个人信息（可发布 GitHub）。

---

## 一、三个部件

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│ 目标机 (任意 Windows/Linux) │        │ 本机 your-harness          │
│                            │        │                              │
│  rdsh.exe  单文件 NativeAOT │        │  DSH Web 面板 :8088          │
│   ├ 生成 TOTP 密钥          │        │   └ dsh-remote 插件          │
│   ├ 显示配对串 + 二维码      │        │       ├ /remote/attach  ←反连 │
│   ├ 本地控制台 + 能力清单    │        │       ├ /remote/ 面板（TOTP） │
│   └ 审计日志 + 一键断开      │        │       └ remote 工具（给我用） │
│                            │        │                              │
│  模式 A（默认）反连：        │◄───────┤  经 Tailscale/局域网，零第三方 │
│    wss 长连到 DSH 中继       │  出网   │                              │
│  模式 B 直连：自带 HTTP 端口 │◄───────┤  同网段直连（或配合隧道）      │
└────────────────────────────┘        └──────────────────────────────┘
```

**关键设计：中继由 DSH 插件自己承担**——不新增任何常驻服务、不新增端口。`rdsh` 主动连到 DSH 已有的 `webServer`（`:8088`）下的 `/remote/attach`，这条 wss 长连就是隧道。目标机只需要「能访问到本机 DSH 的地址」，不需要公网 IP、不需要 Tailscale 装在目标机上（本机已在 tailnet 内，目标机只要能路由到本机即可；同网段自动回退局域网地址）。

## 二、两条腿（拓扑）

| 模式 | 谁主动 | 适用 | 打包 |
|---|---|---|---|
| **A 反连**（默认） | `rdsh` 连 DSH 中继 | 目标机能访问到本机（同 LAN / tailnet / VPN） | 默认启用，无需公网 |
| **B 直连** | DSH 连 `rdsh` 的 HTTP 端口 | 同网段、或用户自备端口映射/隧道 | 默认启用 |
| **C 隧道** | `rdsh` 出网到第三方隧道 | A/B 都不通、目标机在纯公网侧 | 预留接口（cloudflared 等外部二进制作伴生进程），V1 只做检测与提示 |

启动时 `rdsh` 并行探测：能连上 DSH 中继 → 走 A 并打印「已连上控制端」；否则退回 B 并打印本机可达地址。切换不需要用户操作。

## 三、配对与认证

**三件套**：`deviceId`（随机，公开）+ `secret`（32 字节随机，base32 展示 = TOTP 密钥）+ `relayUrl`。

**第 1 步（人在场）**：`rdsh` 首次启动生成三件套，控制台打印二维码 + 一行配对串：

```
DshAgent:<base64url(JSON)>      例：DshAgent:eyJ2IjoxLCJpZCI6ImE3ZjMi...
```

JSON 结构（短键省体积）：`{v,id,url,sec,host,os,arch,listen,ver}`。

**第 2 步**：用户把配对串（或二维码截图）发给我 → 我调 `remote pair`：
- 解析配对串；
- 用 `secret` 现算 TOTP（30s/6位/±1 窗口）向后端证明「我拿到了密钥」——这一步同时验证通路；
- 成功后把设备登记进插件状态文件，**只存 secret 的 HMAC 校验用副本（用于签名，不存明文 TOTP 码）**。

**第 3 步（此后每一跳）**：请求级 HMAC-SHA256 签名，不传明文密钥：

```
X-RDSH-Device: <deviceId>
X-RDSH-Ts: <unix秒>
X-RDSH-Nonce: <16字节hex>
X-RDSH-Sig: base64url(HMAC-SHA256(secret,
              METHOD + "\n" + PATH + "\n" + TS + "\n" + NONCE + "\n" + sha256hex(body)))
```

服务端校验：签名比对（常量时间）→ 时间窗 ±120s → nonce 去重（每设备 LRU，窗口内一次性）→ 每设备令牌桶限流。**密钥永不上网**，上网的只有签名。

**反连握手另加一层**：`rdsh` 连 `/remote/attach?id=<deviceId>` 时带 `Authorization: Bearer base64url(HMAC(secret, "attach:"+deviceId))`，防止陌生设备占用你的中继槽位；中继侧同样按 deviceId 查 secret 校验。

## 四、线协议（方法与帧）

统一 RPC：方法名 + JSON 参数 + JSON 结果。命令执行采用**"启动 → 轮询增量"**，这样直连与隧道复用同一套语义，长输出不需要长连接阻塞。

| 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `hello` | — | host/os/arch/ver/caps/image | 能力协商（含 `node: true/false`） |
| `exec` | command, workdir?, timeoutMs?, env?, shell? | runId | 启动一次命令，立即返回 |
| `poll` | runId, waitMs? | delta / exitCode / done | 增量取输出；`waitMs` 支持长轮询 |
| `kill` | runId, signal? | ok | 终止前台任务 |
| `spawn` | command, workdir?, label? | jobId | 后台脱离任务（跨会话存活） |
| `jobs` | jobId? | 任务列表 / 单任务状态 | 后台任务管理 |
| `read` | path, offset?, maxBytes? | base64 / text | 读文件 |
| `write` | path, base64, mode? | bytes 写入数 | 写文件 |
| `ls` | path | 条目列表 | 目录（含大小/时间） |
| `stat` | path | 类型/大小/mtime | |
| `rm` | path, recursive? | ok | 删除（默认进回收站式重命名，可配硬删） |
| `node` | script(内联) 或 path, args[], cwd? | runId | 完整版才可用；瘦身版返回明确的「未内嵌 Node」错误 |
| `image` | — | 屏幕截图（Windows）/ 降级提示 | 观察目标机界面 |

**大文件传输**：`read`/`write` 走分块 + 流式 base64，单块上限 4MB；DSH 侧工具负责拼装与落盘（落到本机工作区临时目录）。反连通道下，后续可升级为真流式帧（`chunk`/`end`）以避免 base64 膨胀。

## 五、DSH 侧工具（我用的）

单个工具 `remote`，`cmd` 分派（与 `pwsh`/`job_output` 风格一致）：

```
remote info                     # 本机侧该怎么启动（生成给用户的一行命令/说明）
remote pair <配对串|图片内容>    # 解析 + TOTP 校验 + 登记设备
remote list                     # 设备清单：在线状态、主机、系统、最后心跳
remote exec <cmd> [id]          # 同步执行（内部展开 exec+poll 到超时），返回耗时输出
remote exec-bg <cmd> [id]       # 后台 → 返回 jobId，配 remote jobs
remote read/write/ls/stat/rm ...# 文件操作
remote upload <本地> <远端>      # 分块上传
remote download <远端> <本地>    # 分块下载
remote node <脚本|路径> [id]     # 目标机跑 mjs（完整版）
remote jobs [id] [--kill]
remote disconnect <id>          # 断开
```

工具结果渲染成终端卡片（复用 `presentCall/presentResult`），长输出截断并落盘。

## 六、插件结构（host 侧，零依赖）

```
~/.dsh/profiles/web/dsh-remote/
  index.js          # 插件：/remote/attach 中继 + /remote/ 面板 + remote 工具
  panel.html        # 设备面板（TOTP 保护，与 Web 面板/ TG 桥共用密钥）
  devices.json      # 设备登记（secret 只存签名用副本）
  queue/            # 目标离线时的待发请求（有限长度，溢出拒绝）
```

- 挂载方式与现有插件一致：`cordis.patch.yml` 里 `- insert: [{ id: dsh-remote, name: './dsh-remote/index.js', config: {...} }]`。
- 复用 `ctx.webServer`（中继与面板）、`ctx.tools`（注册 `remote` 工具）。
- **面板按钮文案固定「远程 DSH 正在连接」**；面板不出现个人信息，可随仓库一起公开。
- 改源码后需重启 harness 生效（实测确认 `patchReload: live` 只对补丁文件本身生效，插件源码改动不会热加载）。

## 七、安全设计

1. **密钥不上网**：HMAC 签名；secret 只落地在目标机与 DSH 插件状态文件（权限收紧）。
2. **侧信道**：目标机控制台常驻红色状态块「远程 DSH 正在连接」+ 发起方信息 + 本次会话命令计数；`Ctrl+X` 或面板一键断开所有会话。
3. **审计**：目标机本地追加写 `audit.log`（时间/方法/摘要/结果大小/发起方），DSH 侧同样留痕；命令原文我只在必要时记，默认记 hash + 前 200 字符。
4. **限流与回放**：时间窗 ±120s + nonce 一次性 + 令牌桶；认证失败 5 次锁 2 小时（与既有插件同策略）。
5. **最小面**：`rdsh` 只暴露一个 HTTP 端点，其他端口一律不开；默认只监听回环，直连模式需显式 `--listen 0.0.0.0`。
6. **危险动作留痕不拦截**（用户 2026-09-23 决定：全权 + 审计 + 一键断开）；但 `rm` 默认走「先改名再删」的软删除，`--hard` 才真删。

## 八、构建与发布

- **本机（Windows）**：`dotnet publish -c Release -r win-x64` → `rdsh.exe`（AOT 单文件）。
- **离线还原**：当本机 TLS 栈不可用（schannel 故障）时 NuGet 连不上 api.nuget.org；仓库根放 `nuget.config` 声明**无远程源**，全部走本地包缓存 `%USERPROFILE%\.nuget\packages`。Linux 交叉编译需 `runtime.linux-x64.microsoft.dotnet.ilcompiler` 与对应 runtime pack（本机没有）→ 请改在目标 Linux 机器上就地构建（`test/vps-build.sh` 是当时的记录）。
- **两档产物**：
  - `rdsh-slim.exe`（不内嵌 Node，约 5–12MB）：只有 exec/文件/任务；
  - `rdsh-full.exe`（内嵌 Node 运行时 + 必要 npm 资产，约 60–70MB）：多一个 `node` 方法，可在目标机跑 `.mjs`。
- 目录布局见 `README.md`。

## 九、实施顺序（每步都可独立验证）

1. ✅ **NativeAOT 可行性冒烟**（TOTP / HttpListener / JSON 源生成 / 进程派发 / 体积）——先验证再动手。
2. `rdsh` 最小闭环：`hello` + `exec/poll` + 直连 HTTP + TOTP 校验 → 本机自测（本机同时当目标机）。
3. DSH 插件 + `remote` 工具 → 本机同时跑两端，端到端 `exec` 打通。
4. 反连模式（`/remote/attach` wss 中继）→ 端到端。
5. 文件收发 + 后台任务 + 审计 + 面板。
6. `node` 方法（内嵌运行时）+ 两档构建脚本。
7. 跨平台产物（win-x64 / linux-x64 / linux-arm64）、GitHub 发布物料、用户向使用说明。

## 九点五、实施实录与取舍（2026-09-23）

**已落地**：目标机 agent（C# / .NET 8 / **NativeAOT** 单文件，win-x64 实测 **5.9 MB**），
28/28 端到端测试通过（配对串、HMAC 签名、防重放、陈旧时间戳拒绝、exec+poll 流式、
大输出 2000 行不丢、超时终止、后台任务、文件读写、二进制 base64 往返、300 KiB 分块读、
node 跑 mjs、审计留痕、软删除）。

**关键技术结论**：
1. **NativeAOT 在本机完全可用**，但官方包版本号有坑：`Microsoft.DotNet.ILCompiler` 的真实
   版本号与 runtime pack 不同（本地只有 10.0.2），**net8.0 目标必须等 SDK 自己解析**，
   手写 `IlcPackageVersion` 会立刻失败。最终用 `net8.0 + win-x64` 一次成功。
2. **AOT 下禁止反射式 JSON**：`ctx.GetTypeInfo(typeof(T))` 会返回 null；必须为每个类型写
   显式 `JsonTypeInfo` 构造器（`RpcReply.FromHello` 等），并对 `string` 用自写转义而非
   `JsonSerializer.Serialize`。源码生成上下文必须开 `PropertyNamingPolicy = CamelCase`，
   否则落盘配置写成 PascalCase，外部读不到。
3. **`Console.OutputEncoding` 在 stdout 被重定向时抛异常**——必须 try/catch，否则 agent
   在管道/重定向下直接崩。
4. **本机 .NET 的 TLS 栈是坏的**：真实用户环境下 .NET 做任何 HTTPS 都报
   `Win32Exception: 安全包中没有可用的凭证`（连 baidu.com 都不行），而 Node/OpenSSL 正常。
   NuGet 因此必须走代理 + `--configfile nuget.proxy.config`；受限沙箱下即使给代理也无效
   （schannel 需要真实 `%APPDATA%\Microsoft\Crypto` 与系统证书库）。

**明确砍掉的功能**：
- **二维码**：曾实现控制台二维码 + `--qr-png`，但自建编码器在**掩码图案择优**上始终无法与
  参考实现逐模块对齐（version 1 仍有百余模块差异，`cv2.QRCodeDetector` 与 jsQR 均无法解码）。
  投入产出比不划算，已整体删除（QR.cs/Png.cs 及相关测试），**配对串满足核心需求**。
  若日后需要二维码，应在控制器侧用成熟库生成，而不是自建。
- **内嵌 Node 的完整版**：未做。瘦身版已能用目标机 PATH 上的 node 跑 `.mjs`
  （实测通过），内嵌运行时留待需要时再评估。

**下一阶段（未开始）**：DSH 插件（中继 `/remote/attach` + 面板 + `remote` 工具）。
agent 侧的反连 WebSocket 客户端已实现并编译通过，但**中继侧尚未实现，反连链路未做端到端验证**。
## 十、明确不做（V1 范围外）

- 不做真 PTY/交互式 shell（V2 再评估；先给 `spawn` + 输出轮询）。
- 不做内建打洞（UPnP 成功率低）；隧道作为模式 C 只留接口。
- 不做目标机图形化 GUI（控制台 + 可选托盘）。
